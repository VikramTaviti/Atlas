# ATLAS demo script

This script is reproducible without credentials. The benchmark and optimizer outputs are explicitly fixture-only, not real model or production performance claims.

## Dynamic graph and tool governance

1. Run `python examples/runtime_fake.py` and show the fan-out branches completing before the join.
2. Run `python examples/react_fake.py` and show the agent's tool call, observation, and final answer.
3. Inspect the event history:

   ```bash
   atlas inspect-run --events-db /tmp/atlas-react-example.sqlite.events.sqlite --run-id RUN_ID
   atlas replay-tools --events-db /tmp/atlas-react-example.sqlite.events.sqlite \
     --artifacts /tmp/atlas-react-example.sqlite.artifacts --run-id RUN_ID
   ```

4. In a short Python session, call `backend.replay(plan, source_run_id=..., replay_run_id=...)`; point out that tool adapters are not called and agent adapters are explicitly re-executed.

## Evidence-gated improvement

Run `python examples/evidence_gated_improvement.py`, inspect the baseline failure, candidate report, paired sample count, hard gates, and eligible-but-not-promoted result. Then run `python examples/evidence_gated_improvement.py --approve` to demonstrate a separate explicit fixture approval and reversible promotion. All data is generated by deterministic fixture adapters and labelled illustrative.

## Recording

Record the terminal commands and output using the operating system's screen recorder. Keep the `illustrative_fixture_only` label visible when showing benchmark metrics. No recording is checked into the repository; this keeps demo capture reproducible and avoids presenting synthetic results as real measurements.
